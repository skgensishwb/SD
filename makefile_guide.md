(https://www.gnu.org/software/make/manual/html_node/index.html)

## Раздел 1. Обзор make (Overview of make)

Утилита make автоматически определяет, какие части программы нужно
перекомпилировать, и выполняет нужные команды. make не ограничена
только программами — её можно использовать для любой задачи, где одни
файлы должны автоматически обновляться при изменении других.

Чтобы использовать make, нужно написать файл, называемый **makefile**,
который описывает зависимости между файлами программы и содержит
команды для обновления каждого файла. Как только makefile написан,
достаточно одной команды:

    make

чтобы выполнить все необходимые перекомпиляции. make использует данные
из makefile и время последнего изменения файлов, чтобы решить, какие
файлы нужно обновить.

### Как make работает на примере

Допустим, есть программа из нескольких `.c` и `.h` файлов. Когда вы
меняете какой-то `.c` — нужно перекомпилировать только его в `.o`.
Когда меняете `.h` — нужно перекомпилировать все `.c`, которые его
включают. После этого все `.o` (новые и старые) линкуются в
исполняемый файл.

make делает ровно это: проверяет, что изменилось, и пересобирает
только необходимое.

## Раздел 2. Введение в Makefile (An Introduction to Makefiles)

Это самый важный раздел для новичка. Здесь описаны все базовые
концепции.


### 2.1. Как выглядит правило (What a Rule Looks Like)

Простой makefile состоит из **правил** (rules) такой формы:

    цель: зависимости
    	команда
    	команда
    	...

Три компонента:

- **Цель (target)** — обычно имя файла, который нужно создать
  (исполняемый файл, объектный файл). Может также быть именем
  действия, например `clean`.

- **Зависимости (prerequisites)** — файлы, от которых зависит цель.
  Если хотя бы один из них новее цели — цель пересобирается.

- **Команда (recipe)** — действие, которое make выполняет. Может
  состоять из нескольких строк.

**КРИТИЧЕСКИ ВАЖНО:** перед каждой строкой команды должен стоять
символ **TAB** (не пробелы!). Это самая частая ошибка новичков.
Если поставить пробелы вместо TAB, make выдаст ошибку
`missing separator`.


### 2.2. Простой Makefile (A Simple Makefile)

Пример makefile для программы из нескольких файлов:

    edit: main.o kbd.o command.o display.o
    	cc -o edit main.o kbd.o command.o display.o

    main.o: main.c defs.h
    	cc -c main.c

    kbd.o: kbd.c defs.h command.h
    	cc -c kbd.c

    command.o: command.c defs.h command.h
    	cc -c command.c

    display.o: display.c defs.h buffer.h
    	cc -c display.c

    clean:
    	rm -f edit main.o kbd.o command.o display.o

Здесь:
- `edit` — финальный исполняемый файл, зависит от четырёх `.o`
- Каждый `.o` зависит от своих `.c` и `.h` файлов
- `clean` — не файл, а действие; запускается только явно: `make clean`


### 2.3. Как make обрабатывает Makefile (How make Processes a Makefile)

По умолчанию make начинает с **первой цели** в файле. Это называется
**цель по умолчанию** (default goal). Поэтому первым правилом обычно
ставят сборку всей программы.

Алгоритм работы make:

1. Прочитать makefile
2. Найти первую цель (например, `edit`)
3. Прежде чем собирать `edit`, проверить его зависимости (`main.o`,
   `kbd.o` и т.д.)
4. Для каждой зависимости рекурсивно проверить её зависимости
5. Если зависимость новее цели или цель не существует — выполнить
   команду
6. Подниматься обратно вверх по дереву зависимостей

Пример: если изменить `command.c`, make:
- Увидит, что `command.c` новее `command.o`
- Перекомпилирует `command.o`
- Увидит, что `command.o` новее `edit`
- Перелинкует `edit`

Правило `clean` не является зависимостью `edit`, поэтому при простом
вызове `make` оно не выполняется.


### 2.4. Переменные делают Makefile проще (Variables Make Makefiles Simpler)

Чтобы не повторять один и тот же список файлов, используют переменные:

    objects = main.o kbd.o command.o display.o

    edit: $(objects)
    	cc -o edit $(objects)

    clean:
    	rm -f edit $(objects)

Переменная определяется как `имя = значение`, а используется как
`$(имя)`. Это просто текстовая подстановка.

Принятые соглашения:
- ВЕРХНИЙ РЕГИСТР — для переменных, которые пользователь может
  переопределить (CXX, CFLAGS)
- нижний регистр — для внутренних переменных makefile


### 2.5. Автоматический вывод команд (Letting make Deduce the Recipes)

make имеет встроенные **неявные правила** (implicit rules). Например,
make знает, что `.o` файл собирается из `.c` файла командой
`cc -c файл.c -o файл.o`.

Поэтому можно не писать команды компиляции:

    objects = main.o kbd.o command.o display.o

    edit: $(objects)
    	cc -o edit $(objects)

    main.o: defs.h
    kbd.o: defs.h command.h
    command.o: defs.h command.h
    display.o: defs.h buffer.h

make сам догадается, как компилировать каждый `.o` из `.c`.


### 2.6. Правило для очистки (Rules for Cleaning the Directory)

    .PHONY: clean
    clean:
    	rm -f edit $(objects)

`.PHONY` говорит make, что `clean` — это не имя файла, а действие
(phony target). Без этого, если в директории окажется файл с именем
`clean`, правило не сработает.

## Раздел 3. Написание Makefile (Writing Makefiles)

### Что содержит Makefile

Makefile может содержать пять типов элементов:

1. **Явные правила** (explicit rules) — говорят, когда и как
   пересобирать конкретные файлы
2. **Неявные правила** (implicit rules) — описывают, как обрабатывать
   файлы по шаблону (например, все `.c` → `.o`)
3. **Определения переменных** — текстовые строки для подстановки
4. **Директивы** — специальные инструкции (include, ifdef и т.д.)
5. **Комментарии** — начинаются с `#`

### Длинные строки

Строку можно разбить символом `\` в конце:

    objects = main.o kbd.o \
              command.o display.o

### Имя файла

make ищет файлы в порядке: `GNUmakefile`, `makefile`, `Makefile`.
Рекомендуется использовать `Makefile` (с большой буквы), так как он
хорошо заметен в листинге директории.

### Включение других makefile

    include другой_файл.mk

Полезно, когда несколько проектов используют общие переменные или
правила.

### Две фазы обработки

make работает в две фазы:
1. **Фаза чтения**: читает все makefile, строит граф зависимостей,
   определяет все переменные
2. **Фаза выполнения**: определяет, какие цели нужно пересобрать, и
   выполняет их команды

## Раздел 4. Написание правил (Writing Rules)

### Синтаксис правила

    цели: зависимости
    	команда

или:

    цели: зависимости ; команда

Цели и зависимости — имена файлов, разделённые пробелами.

### Wildcards (подстановочные символы)

В makefile можно использовать `*`, `?`, `[...]` — как в shell:

    clean:
    	rm -f *.o

    objects = $(wildcard *.o)

Важно: в переменных `*` не раскрывается автоматически. Используйте
функцию `$(wildcard шаблон)`.

* '*' — любое количество любых символов. *.o значит "все файлы, заканчивающиеся на .o": main.o, text.o, mystring.o...
* ? — ровно один любой символ. file?.c совпадёт с file1.c, fileA.c, но не с file10.c
* [...] — один символ из набора. file[123].c совпадёт с file1.c, file2.c, file3.c. Можно задавать диапазоны: [a-z], [0-9]

### VPATH — поиск файлов в других директориях

Если исходники лежат в другой директории:

    VPATH = src:../headers

make будет искать файлы-зависимости в указанных директориях.

Более точный вариант — директива `vpath` (с маленькой буквы):

    vpath %.c src
    vpath %.h include

Это говорит: искать `.c` файлы в `src`, а `.h` файлы в `include`.

**Важно**: VPATH предназначен для поиска исходников (зависимостей),
а не для размещения целей.

### Phony-цели (Phony Targets)

Phony-цель — это не имя файла, а просто имя действия:

    .PHONY: clean all install

    clean:
    	rm -f *.o program

    all: program tests

Зачем `.PHONY`:
1. Если в директории случайно есть файл `clean`, без `.PHONY`
   make скажет "clean is up to date" и ничего не сделает
2. Небольшое ускорение — make не пытается искать файл

## Раздел 5. Команды в правилах (Writing Recipes in Rules)

### Каждая строка — отдельный shell

Каждая строка команды выполняется в **отдельном** процессе shell.
Это значит:

    target:
    	cd subdir
    	pwd          # НЕ выведет subdir! Это уже другой shell

Чтобы выполнить в одном shell, объедините через `&&` или `\`:

    target:
    	cd subdir && pwd

    # или:
    target:
    	cd subdir; \
    	pwd

### Подавление вывода команд

По умолчанию make печатает каждую команду перед выполнением. Чтобы
подавить — поставьте `@` перед командой:

    @echo "Компиляция завершена"

### Игнорирование ошибок

Чтобы make не останавливался при ошибке:

    clean:
    	-rm -f *.o   # минус перед командой — игнорировать ошибки

## Раздел 6. Переменные (Using Variables)

### Определение и использование

    CXX = g++
    CXXFLAGS = -Wall -g

    program: main.o
    	$(CXX) $(CXXFLAGS) main.o -o program

### Два типа переменных

**Рекурсивные** (recursive, оператор `=`):
- Раскрываются при каждом использовании
- Могут ссылаться на переменные, которые определены позже

    FOO = $(BAR)
    BAR = hello
    # $(FOO) будет "hello"

**Просто раскрываемые** (simply expanded, оператор `:=`):
- Раскрываются один раз в момент определения
- Работают как обычные переменные в языках программирования

    FOO := $(BAR)    # если BAR ещё не определён — FOO будет пустым
    BAR := hello

Рекомендация: используйте `:=` для предсказуемости, если не нужна
ленивая подстановка.

**Другие операторы:**
- `+=` — добавить к переменной: `CFLAGS += -O2`
- `?=` — присвоить только если ещё не определена:
  `CC ?= gcc`

### Автоматические переменные

Вычисляются заново для каждого правила:

- `$@` — имя цели
- `$<` — первая зависимость
- `$^` — все зависимости (без дубликатов)
- `$?` — зависимости, которые новее цели
- `$*` — «основа» (stem) при сопоставлении шаблона

Пример:

    %.o: %.c
    	$(CC) -c $< -o $@

Здесь `$<` — это `файл.c`, а `$@` — это `файл.o`.

### Стандартные переменные

make использует ряд предопределённых переменных:

- `CC` — компилятор C (по умолчанию `cc`)
- `CXX` — компилятор C++ (по умолчанию `g++`)
- `CFLAGS` — флаги для C-компилятора
- `CXXFLAGS` — флаги для C++-компилятора
- `CPPFLAGS` — флаги для препроцессора (-I, -D)
- `LDFLAGS` — флаги для линковщика (-L)
- `LDLIBS` — библиотеки для линковки (-l)

Переопределяя эти переменные, вы управляете поведением встроенных
правил без необходимости писать свои.

## Раздел 7. Неявные правила (Implicit Rules)

### Шаблонные правила (Pattern Rules)

Символ `%` в цели означает шаблон:

    %.o: %.c
    	$(CC) $(CFLAGS) $(CPPFLAGS) -c $< -o $@

Это правило говорит: любой файл `что-угодно.o` собирается из
соответствующего `что-угодно.c`. `%` совпадает с одной и той же
строкой в цели и зависимости.

### Встроенные неявные правила

make уже знает многие стандартные правила. Основные:

- `файл.o` из `файл.c`: `$(CC) $(CPPFLAGS) $(CFLAGS) -c`
- `файл.o` из `файл.cpp`: `$(CXX) $(CPPFLAGS) $(CXXFLAGS) -c`
- `файл` из `файл.o`: `$(CC) $(LDFLAGS) файл.o $(LDLIBS) -o файл`

Чтобы увидеть все встроенные правила: `make -p`

### Цепочки правил

make может строить цепочки. Например, если есть `файл.y` (Yacc),
make знает: `файл.y` → `файл.c` → `файл.o`.

## Раздел 8. Условные конструкции (Conditionals)

    ifdef DEBUG
    CFLAGS += -g -DDEBUG
    else
    CFLAGS += -O2
    endif

Доступные директивы: `ifeq`, `ifneq`, `ifdef`, `ifndef`.

    ifeq ($(CXX), g++)
    CXXFLAGS += -Wextra
    endif

## Раздел 9. Функции (Functions)

### Основные функции для работы с текстом

    $(subst from,to,text)     # замена подстроки
    $(patsubst %.c,%.o,$(SRC))  # замена по шаблону
    $(wildcard *.c)           # список файлов по шаблону
    $(addprefix src/,$(SRC))  # добавить префикс
    $(addsuffix .o,$(NAMES))  # добавить суффикс
    $(filter %.c,$(FILES))    # отфильтровать по шаблону
    $(filter-out %.h,$(FILES)) # исключить по шаблону
    $(sort $(LIST))           # сортировка + удаление дубликатов
    $(word n,text)            # n-е слово
    $(words text)             # количество слов
    $(shell команда)          # выполнить shell-команду

Пример:

    SRC = $(wildcard src/*.c)
    OBJ = $(patsubst src/%.c, build/%.o, $(SRC))

    build/%.o: src/%.c
    	$(CC) $(CFLAGS) -c $< -o $@

## Практический пример: Makefile для C++ проекта

    CXX      := g++
    CXXFLAGS := -Wall -Wextra -g -fsanitize=address
    LDFLAGS  := -fsanitize=address

    # Автоматически находим все .cpp файлы
    SRC := $(wildcard *.cpp)
    OBJ := $(SRC:.cpp=.o)
    TARGET := program

    .PHONY: all clean

    all: $(TARGET)

    # Линковка
    $(TARGET): $(OBJ)
    	$(CXX) $(LDFLAGS) $^ -o $@

    # Компиляция (шаблонное правило)
    %.o: %.cpp
    	$(CXX) $(CXXFLAGS) -c $< -o $@

    # Зависимости от заголовков (вручную)
    main.o: text.hpp mystring.hpp
    text.o: text.hpp mystring.hpp
    mystring.o: mystring.hpp

    clean:
    	rm -f $(OBJ) $(TARGET)

### Что здесь происходит:

1. `all` — цель по умолчанию, собирает `program`
2. `$(TARGET): $(OBJ)` — линкует все `.o` в исполняемый файл.
   `$^` раскрывается в список всех зависимостей
3. `%.o: %.cpp` — шаблонное правило: каждый `.o` собирается из `.cpp`.
   `$<` — первая зависимость (сам `.cpp`), `$@` — цель (`.o`)
4. Отдельные строки с зависимостями от `.hpp` файлов — без команд,
   они просто добавляют зависимости к уже существующему шаблонному
   правилу
5. `clean` — удаляет все артефакты сборки

## Шпаргалка: основные команды make

| Команда             | Действие                                    |
|---------------------|---------------------------------------------|
| `make`              | Собрать первую (default) цель               |
| `make clean`        | Выполнить цель `clean`                      |
| `make -j4`          | Параллельная сборка (4 потока)              |
| `make -n`           | Показать команды, но не выполнять           |
| `make -p`           | Показать все правила и переменные           |
| `make -B`           | Пересобрать всё принудительно               |
| `make VAR=value`    | Переопределить переменную из командной строки|
| `make -f имя_файла` | Использовать другой makefile                |

## Шпаргалка: автоматические переменные

| Переменная | Значение                              | Пример                |
|------------|---------------------------------------|-----------------------|
| `$@`       | Имя цели                             | `main.o`              |
| `$<`       | Первая зависимость                    | `main.cpp`            |
| `$^`       | Все зависимости (без дубликатов)      | `main.cpp defs.h`     |
| `$?`       | Зависимости новее цели                | (изменённые файлы)    |
| `$*`       | Основа шаблона (stem)                 | `main` (из `main.o`)  |
| `$(@D)`    | Директория цели                       | `build`               |
| `$(@F)`    | Имя файла цели (без директории)       | `main.o`              |
